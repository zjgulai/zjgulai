# GitHub 主页精细化优化设计

## 目标

面向中国跨境品牌管理层，将主页从“项目陈列”升级为“可核验的决策系统能力说明”，并确保整个可编辑主页介绍不出现以下字符串及大小写变体：

- `Momcozy`
- `lute`
- `路特`

“可编辑主页介绍”包括 GitHub Profile 元数据、README、置顶仓库卡片、链接文字与目标、图片 alt、SVG 元数据、资源文件名和图片可见像素；不包括 GitHub 自动生成的历史贡献动态、提交历史和其他仓库内部页面。

## 对抗性审计结论

1. 仅重写 README 正文无法达标：Company、Website、Pins、链接、alt、SVG title、文件名和图片像素仍会暴露关键词。
2. 6 张现有视觉资产中有 5 张存在关键词或品牌标识；只有 `paper-to-skills.webp` 没有直接命中。
3. 当前案例截图在 390px 移动端只显示约 308px 宽，后台界面小字无法承担信息传递。
4. 当前公开 Stars 数量不足以成为管理层背书；更强的公开证据是数据规模、验收报告、测试数量、治理边界和可追溯产物。
5. 能力图与后续表格表达重复，应减少抽象分类，提前展示决策价值和证据。

## 采用方案

采用“从市场信号到经营动作”方案。

核心价值主张：

> 为中国跨境品牌构建可核验的决策系统：把消费者信号、研究证据和供应链口径，转化为有负责人、有边界、可持续运营的经营动作。

叙事顺序：

1. 一句话说明服务对象和业务结果。
2. 首屏展示三个可核验数字，建立可信度。
3. 用“信号 → 证据 → 决策 → 行动”解释方法。
4. 用三个管理层场景说明能力：消费者洞察、供应链治理、AI 能力治理。
5. 用公开项目清单承接核验，不依赖特定客户品牌背书。

## 视觉策略

- 保留米白、深蓝、克制红的现有视觉识别。
- Hero 改为移动优先，删除品牌角标，把两行价值主张和三个证据数字放在首屏。
- 删除四张密集后台截图，改为一张可缩放的“决策闭环”SVG 和 Markdown 证据卡片。
- SVG 只保留少量大字；关键结论同时存在于 Markdown，避免信息只存在于像素中。
- 普通文字对比度不低于 4.5:1，大字不低于 3:1。

## 内容与证据

主页只引用公开仓库中可核验且不会被误读的事实：

- `Agent_skills`：公开 registry 中 164 个 managed skills。
- `Agent_hook`：公开 registry 中 9 个 hook manifests；README 记录 81 tests。
- `scm`：30 项 P0 owner sign-off、18 项 P0 字段映射；明确标注为只读原型，不能描述为已接入生产 ERP。
- `paper_to_skills`：4 步研究转化流程与审核阈值 ≥7/10。
- `kgraph`：3 份内置 Playbook 快照与 readonly/CAS/原子写入边界。
- `data_achieve`：公开的数据到证据、报告和告警链路。

不采用以下内容：

- 未提供清晰来源链的市场规模或罚款数字。
- Stars、Forks 等不足以构成影响力的指标。
- 含目标关键词的客户案例名称、域名、截图和资源文件名。
- 存在公开数字冲突的 `Agent_mcp` 描述。

## 置顶仓库

推荐顺序：

1. `data_achieve`
2. `scm`
3. `paper_to_skills`
4. `Agent_skills`
5. `Agent_hook`
6. `kgraph`

选择 `data_achieve` 而不是 `melwater_ana`，是为了让用户点击项目后也尽量保持去品牌化叙事；这不是硬性主页验收范围，但能降低后续跳转风险。

6. 本地变更经用户明确批准后才 commit、push 和修改公开 Profile/Pins。
